# 使用说明

输入一个数据集文件夹，运行评估，再打开结果报告。不需要先转换成统一表格，也不需要手工整理字段。

## 1．选择数据集文件夹

直接选择现有文件夹，保留子目录和原始文件名。同一个数据集已有的以下材料可以一起放入：

| 材料 | 通俗说明 | 是否必须 |
| --- | --- | --- |
| 日志或网络流量 | 要评估的原始数据 | 必须 |
| 标签 | 标明哪些记录正常、哪些与攻击有关 | 有就提供 |
| 攻击过程说明 | 已知发生了哪些攻击、各有哪些步骤，也称GT | 有就提供 |
| 防御材料 | 告警、拦截、隔离等记录及处理结果 | 有就提供 |

系统负责识别文件、读取内容和关联记录。没有的材料不用补写，关联不上的材料会留下原因；相关项目可能记0分。

目前可读取已适配的文本日志、表格日志、网络抓包及压缩包，包括 JSON、CSV、XML、PCAP 等。不是所有格式都能自动处理，例如原生 EVTX 日志、图片或 PDF 中的攻击说明尚不支持通用读取；遇到这些情况需要补充程序适配，不是要求你照着内部字段表改写数据。

一次只评估一个数据集，不要混入其他数据集、旧评估结果或程序文件。处理大数据时，给结果所在磁盘留出足够空间，压缩包解压和中间统计也会占用空间。

## 2．首次配置

使用 Python 3.9 或以上版本。在项目目录打开终端，运行：

```bash
python -m pip install -r requirements.txt
```

把项目中的 `.env.example` 复制一份，命名为 `.env`。用文本编辑器打开，填写：

| 配置名称 | 填什么 |
| --- | --- |
| `AI_BASE_URL` | 模型服务提供的接口根地址，不含末尾的`/chat/completions` |
| `AI_MODEL` | 要使用的模型名称 |
| `AI_API_KEY` | 该服务的密钥 |

模板预填了 DeepSeek 地址和模型。可以换用其他提供 OpenAI 兼容接口的服务；更换时把 `AI_THINKING` 改成 `omit`，其他特殊要求见[高级配置](internal/MAINTENANCE.md)。`.env` 只保存在本地，不进入发布包。

联网评估会把必要的格式样本和核验证据发送到你配置的模型服务。数量统计和分数计算在本地完成。

## 3．运行评估

把下面两处路径换成自己的文件夹路径：

```bash
python run.py --input "数据集文件夹路径" --output "新的结果文件夹路径"
```

结果文件夹可以尚未创建；如果已经存在，应当为空。输入和输出放在不同位置，不能相互包含。系统只读原始数据，报告和中间文件写入结果文件夹。

如果不希望调用模型，可以离线运行：

```bash
python run.py --input "数据集文件夹路径" --output "新的结果文件夹路径" --offline
```

离线时仍做本地统计，但无法利用模型理解陌生格式、核验标注含义、攻击步骤、攻击关联及防御含义，相关未确认部分不得分；R01、A03、A04没有语义核验时记0分。

## 4．查看结果

打开结果文件夹里的 **`report.md`**，按下面顺序看：

1. **是否处理完成**：只有全部数据处理完成，才给出正式总分。
2. **总分和三个方面的分数**：均为百分制，总分按全面性35%、真实性40%、对抗性25%合成。
3. **各项得分原因**：重点看哪些材料缺失、哪些内容无法识别或尚未证实。
4. **语义核验是否完成**：R01列出每个攻击步骤、关联记录和判断；A04列出每个防御动作的执行与结果。没有证据、判断矛盾和请求未完成会分别标明，不从分母中删除。
5. **详细报告**：需要核查某项结果时，再点击报告里的明细链接。

真实性中的时间与行为分数表示与内置参考数据的统计规律接近程度，不是“数据为真的概率”。防御评分需要能关联到原始执行与结果的材料，不能单凭告警或措施名称得分。全部已声明防御动作都会进入检查流程，不再设置抽查总量上限。比较数据集时应使用相同系统版本、模型和配置。

| 看到的情况 | 怎么理解或处理 |
| --- | --- |
| 某项是0分 | 先看原因，可能是没有材料、未识别或证据不足，不一定说明数据本身没有该内容 |
| 没有总分 | 全部数据还未处理完成，不能当作正式评价 |
| 有告警，但防御执行项没分 | 告警不等于实际执行了拦截或隔离，需要已有执行记录支持 |
| 提示格式不支持或关联失败 | 查看具体文件和原因，交给维护人员补充适配；不要编造字段来凑分 |
| 网络或模型请求失败 | 检查网络、密钥和服务配置后继续原任务 |
| 提示空间不足 | 选择空间更大的磁盘保存结果，重新运行 |

恢复中断任务时，在原命令后增加 `--resume`，输出仍指向原结果文件夹。只有输入、模型和配置都没变时才这样恢复；有变化就使用新的结果文件夹。

普通使用只需阅读报告。`quality_score.json` 是给其他程序读取的分数文件；其余文件保留了统计和判断过程，需要复查时再看。运行结果可能包含原始记录内容，不随代码上传到公开仓库。

从1.0.1起，R01改为模型语义核验。此前的R01来源追溯分不能直接当作新分数；比较新旧结果需要重新评估。

从1.0.2起，A03、A04也使用模型语义核验，旧固定规则得分不能直接沿用。需要复查时打开`adversarial/defense_semantics/report.md`，查看逐动作依据。

从1.1.0起取消R01和A04的数量抽查。R01有步骤时以步骤为单位评分，无步骤时以全部已有标签记录评分；报告标明采用的口径。有步骤时，未关联步骤的标签仍逐条检查并列出，作为辅助诊断，不混入步骤分母。材料多时调用次数会增加；程序分批处理并缓存相同请求。旧版结果需在新输出目录重跑，不能直接横向比较。
